## 交付定位

这是实施方案的**首个可运行版本**：完成独立仓库、权限与主题、模拟来源、查询、同步验证、工单、模拟双人审批、对账和导出，并提供真实 HTTP 只读适配契约。不是整个 19–27 人天计划的生产验收。

本次没有修改 `mishu-platform` 或 `mishu-prompt-guard` 的业务代码、数据、进程。主平台此前已有的未提交改动保留；独立后台的业务数据是新建的合成数据。

## 测试

`npm run build` 通过。`npm test` 使用隔离 Schema；自动化场景覆盖：

- 跨应用访问、角色、CSRF、撤权、所有管理查询 SQL、错误整数和日期。
- 双人审批、请求并发幂等、退款并发竞争、过期或撤权、陈旧订单、真实命令强制关闭。
- 来源成功后响应丢失，通过原命令回执恢复；不因后来撤权而丢失成功事实。
- 快照摘要/余额失败整体回滚，快照期间发生退款后补事件，导入激活后崩溃恢复。
- 重复、乱序、缺口、同编号内容冲突、不可变流水冲突；对账差异与历史保留。
- 原生 Excel 下载鉴权、金额大整数精度、JSONL 完整分录、导出过期/取消/撤权/租约恢复、并发排队上限。
- Excel 详情超出单元格长度时明确报错；智能格式改用 JSONL，内容无截断。
- 本地 HTTP 来源认证、Schema 解析与游标覆盖校验。

`npm run test:ui` 在真实 Chromium 和隔离 HTTP 服务中通过登录、分页、双人审批、工单领取、自动更新、原生 XLSX 下载、对账、流水展开、深浅主题和手机布局；没有浏览器脚本异常。截图保存到忽略目录 `.local/ui-tests/`。

容量测试复现命令 `npm run test:scale`，使用隔离 Schema，产生 10 万订单、100 万条平衡分录，校验压缩文件和 Excel 中每一行。结果与数据形状见 [capacity.md](capacity.md)。

备份恢复验证确认本地演示库 128 笔订单、516 条分录及审计可以恢复且分录守恒。数据库恢复与命令结果恢复分别有测试；这不代表已完成真实业务平台的跨系统灾难恢复演练。

## 明确未完成的阶段

1. **主平台接入改造**：独立联调分支、SQLite 事务发件箱、所有记账入口覆盖、版本和内部读取端点、原业务交易/生成回归。当前真实平台数据还没有流入本后台。
2. **大来源初始导入**：当前首个完整快照上限 50 MiB、1 万订单、5 万记账事务；后续要实现不可变分块清单、校验、断点续传、在线重新建副本。百万分录导出测试不能证明百万分录来源导入已完成。
3. **正式退款接入**：真实来源命令原子去重、与交付/自动超时竞争、业务理由与限额、独立审批人员和二次认证。当前仅模拟来源允许受控退款。
4. **运营与部署增强**：多真实来源逐应用连接配置、应用新增管理、角色/范围变更工作流、定时对账、趋势汇总表、历史分区、磁盘配额/外部告警、异地备份与恢复目标、真实部署容量验收。
5. **更多导出与规模交互**：对账差异专用导出、列表精确计数缓存、超大异步查询。核心数据列表支持页码/游标，工单和审计等辅助列表当前展示有限条数，审计可翻到更早记录。
6. **容器实机验收**：模板已提供，尚未在本机运行 Docker 完成验收。

真实支付、提现、任意余额调整、强制结算、已交付或已结算交易售后均未纳入此版，不提供可执行入口。
