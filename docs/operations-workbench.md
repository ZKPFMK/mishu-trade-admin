# 运营待办、工单检索与关联导航

本轮计划及三轮审查见 [改造计划](operations-upgrade-plan.md)。界面继续使用独立后台的数据副本；所有资金处理仍走原有来源校验、独立审批及幂等命令。

## 个人账号与岗位识别

管理员、运营人员、审批员和审计员共用一个登录页面，邮箱默认留空，使用分配给本人的账号登录。岗位和应用范围取自服务端授权，不在登录页自行选择角色。

登录后，各页面显示“当前登录身份”，包括本人姓名、邮箱、岗位、当前授权应用和可访问应用数量。首页待办、菜单和操作继续按权限显示；多人共用一个登录页面不意味着共用账号或权限。

## 从首页处理待办

工作概览顶部显示当前应用的运营待办，每 10 秒更新，不受下方经营图表日期影响。点击卡片进入对应列表。

| 待办         | 统计口径                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| 待我审批     | 当前账号具备审批角色、申请人为其他人、仍待审批；真实申请还须未过申请有效期。模拟申请没有申请过期规则 |
| 我的开放工单 | 当前账号具备处理角色、本人领取、状态仍开放                                                           |
| 待领取工单   | 当前应用全部未领取的开放工单                                                                         |
| 结果待确认   | 当前应用的 `execution_unknown` 申请；与执行失败区分，系统继续查询原命令                              |
| 开放对账差异 | 当前应用仍为 `open` 的对账差异                                                                       |

统计按应用的来源模式选择模拟或真实申请表，不把两种来源的申请混算。不具备相关角色时不显示“待我审批”或“我的开放工单”。待办并不保证来源当前仍允许执行，提交或审批时仍须通过既有权威校验。

## 查工单和差异

“异常与审批”提供“处理申请”和“异常工单”两个视图，默认进入处理申请。工单支持：

- 按工单编号或订单编号精确检索，按部分标题检索；`%`、`_` 按普通字符处理。
- 按开放/关闭状态，以及本人领取/未领取筛选。
- 每页 25 条，前 1000 页直接跳转；之后继续使用游标翻页，无 200 条历史截断。
- 点击工单编号打开完整详情和全部追加记录，详情地址可直接打开或刷新。
- 原有领取、追加说明、本人关闭约束不变。新建工单后直接定位新记录。

对账差异也支持按状态、差异或对象编号检索及分页；首页的“开放对账差异”可查看全部开放差异。领取不代表问题已消除，消除仍以后续完整对账为依据。

运营处理申请表中的关联工单选择改为查询本人已领取的开放工单，支持按编号/部分标题搜索与继续翻页。非积分补偿操作同时匹配订单，最终仍由服务器检查工单负责人及目标。

列表是实时视图，记录更新后可能改变所在页；需要完整、固定截止点的业务数据导出时使用既有导出功能。新标签打开游标地址若没有前页记录，“上一页”返回该列表首页；不会离开当前后台。

## 保留查询位置并关联对象

列表筛选、应用、页码、游标及订单/工单详情编号保存在 hash URL；刷新和浏览器前进后退可恢复查询位置。侧栏在当前浏览器会话中记住最近访问的位置。切换应用清除导航上下文，防止沿用另一应用的游标；所有后端查询继续校验应用范围。

- 订单详情可打开买卖双方账户、关联流水、工单和审批。
- 账户编号可打开含该账户分录的全部流水；按账户过滤时仍返回完整记账事务，保留其他对手分录。
- 分录账户可返回账户列表；交易托管/结算/退款流水可打开关联订单。
- 生成任务与其他非订单流水使用关联编号查询流水，不把其编号当作订单。
- 工单及审批记录可打开关联对象；真实审批记录也可打开原工单。

密码、验证码和服务 token 不写入导航地址或导航会话存储。公开深链接仍需要登录及对应权限。

## 检索审计

操作审计支持操作者编号、操作类型、对象编号及上海自然日的开始/结束日期筛选。三个编号/类型字段均精确匹配，例如操作类型 `case.note`；操作者编号可从现有审计记录查看。筛选后仍可查询更早记录。

应用级审计继续按当前应用隔离；没有应用归属的事件仍只显示本人事件。新增筛选不会扩大可见范围，也不提供编辑或删除审计记录的入口。

## 接口与兼容

| 接口                                             | 用途                                                              |
| ------------------------------------------------ | ----------------------------------------------------------------- |
| `GET /admin/workbench`                           | 角色相关的待办计数，整数为十进制字符串，无权限的角色项返回 `null` |
| `GET /admin/case-worklist`                       | 完整工单工作列表，含筛选、总数和下一页游标                        |
| `GET /admin/cases/:id`                           | 当前应用下的完整工单详情                                          |
| `GET /admin/work-queue`                          | 当前来源模式的申请工作列表，可筛选 `inbox=approval` 或 `unknown`  |
| `GET /admin/finding-worklist`                    | 对账差异工作列表                                                  |
| `GET /admin/audit-events`                        | 既有数组响应，增加人员、类型、对象、日期筛选                      |
| `GET /admin/journal-transactions?account_id=...` | 包含指定账户分录的记账事务，账户条件也可用于分账列表及导出筛选    |

上述管理接口均要求 `application_id` 和现有 Session，包含详情接口。旧 `/admin/cases` 保持最近 200 条数组响应；新界面及运营表单使用新的分页接口。新工作列表返回 `{items,total,page,limit,next_cursor}`，游标绑定应用、用户与筛选，保留数据库微秒时间。

## 验证和剩余范围

```sh
npm run build
npm test
CHROMIUM_PATH=/absolute/path/to/chrome npm run test:ui
CHROMIUM_PATH=/absolute/path/to/chrome npm run test:workbench:ui
```

隔离测试覆盖 235 条工单/差异、精确整数、角色与跨应用边界、非法日期及游标、旧接口兼容；浏览器覆盖待办入口、较早工单的申请关联、深链接、刷新与前进后退、应用切换、审计、原有退款/导出/对账及深浅色/390px 布局。截图只含合成测试数据，保存在忽略目录 `.local/ui-tests/`。

本轮不包含 Worker 健康监控、自动对账/外部通知、工单转交/附件/期限、权限变更审批、模糊订单搜索或大来源导入。现有生产部署、单来源及导入容量限制仍须按相关文档另行处理。
