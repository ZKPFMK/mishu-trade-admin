# 查询与导出容量测试

时间：2026-10-23。复现：`npm run test:scale`。原始机器报告写入忽略目录 `.local/benchmarks/scale.json`。

测试运行在本机 Apple M4 Pro、14 逻辑核心、24 GiB 内存，macOS arm64，Node.js 26.5.0、本地 PostgreSQL 18。使用随机隔离 Schema，测试后删除。数据库和其他本地服务共享机器资源，无独立负载隔离。

## 数据形状

- 100,000 笔订单，每笔携带约 420 个汉字的素材标题，详情包含完整 JSON。
- 100,000 个结算事务，每个有 10 条分录，共 1,000,000 条；含托管、卖家、服务费、创作者和 6 个上游分配。单事务分录守恒。
- 价格、时间、角色有较强规律，长标题内容重复，因此压缩率较高；不代表真实随机长文本或真实业务分布。
- 总数据库占用约 625 MiB。为查询/导出基准直接构造副本，账户时点余额和订单生命周期没有按真实完整历史生成；不把这份基准当作对账或来源快照验收。

| 精确编号检索（含计数）        |                          26.14 ms |
| 日期范围查询（含计数）        |                           8.01 ms |
| 游标下一页（含计数）          |                           3.50 ms |
| 100 万分录 JSONL.gz 导出      |                          11.28 秒 |
| JSONL 分包数                  |             20 包，每包 50,000 行 |
| JSONL 压缩总大小              |                    4,613,452 字节 |

这是一轮本机测试，不是并发吞吐或 p95/p99 延迟承诺。没有把 RSS 解释为单独 Worker 的生产内存上限，也没有测多应用并发、大量随机长文本、远程存储、长期运行或生产数据库负载。

## 已设边界

- 单个导出 Worker 循环顺序处理任务，同步和命令单独循环。
- 普通列表上限 100 条/页，前 1,000 页可直达，之后用游标与日期过滤。
- 导出批次采用稳定排序游标读取，不重复做全量计数，不把全部结果载入内存。
- 每包最多 50,000 行或约 32 MiB 内容；任务内容及最终文件总量限制 2 GiB，超限明确失败，不静默截断。
- `auto` 根据预计输出行数选择格式；流水按分录行数估算。显式 `xlsx` 保持 Excel。
- Excel 单元格超过 32,767 字符时显式失败；自动格式会把长详情改为 JSONL 保存全部内容。
- 导出关闭页面后继续、进度可查，文件 24 小时到期。当前页、筛选、原生下载、权限回收、取消、重试、租约恢复由集成与浏览器测试覆盖。

**此测试只验收查询与导出。** 当前来源初始导入仍有单快照大小和记录数上限；大规模来源分块导入在后续阶段实施。
