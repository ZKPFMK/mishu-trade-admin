# 交易数据概览

入口：工作概览。图表沿用 MiShu 的深浅主题、荧光绿强调色与响应式卡片布局；每 10 秒自动刷新，切换应用时清除上一应用的展示数据。模拟和主平台应用各自统计，不混合计算。

## 可视化与交互

| 模块         | 内容                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| 核心指标     | 成交积分、退回积分、当前订单托管余额、平台服务费；明确时间范围时展示前一等长时段对比                   |
| 交易趋势     | 积分视图：成交和退款；笔数视图：新增订单、结算和退款笔数；悬停或左右方向键查看精确值，支持展开数据表   |
| 订单环形图   | 按订单笔数或订单原价积分切换；图例展示占比，点击可突出显示对应状态；另显示完成占比、参与买家和卖家数量 |
| 实际分账构成 | 卖家到账、平台服务费、作者版税、上游版税，使用真实结算分录及相对成交积分的占比                         |
| 交易类型分析 | 所有权、使用许可、展示许可及兼容的授权许可；笔数与订单原价积分两种视图                                 |
| 作品成交排行 | 按已结算积分降序排列前 6 个资产，显示结算笔数；相同标题的不同资产仍分别统计                            |
| 当前积分分布 | 用户可用积分、订单托管、生成任务冻结、许可报价托管、私密检索冻结                                       |

默认最近 30 个上海自然日（含今天）；可选近 7 天、近 90 天、全部时间，或自定义日期后点击箭头应用。无数据时显示零值或空状态，不生成演示数据补图。

## 统计口径

- 成交、退款、服务费、版税和作品排行按 **记账时间** 筛选。成交积分使用结算事务的托管转出全额；结算笔数按去重事务计数，不因多条分账分录而重复累计。
- 订单环形图、交易类型、参与人数和新增订单趋势按 **下单时间** 筛选，展示这些订单的**当前状态**。它们不代表某个历史日的状态快照，也不能用当日新增订单数解释当日所有结算。
- 完成占比为当前 `COMPLETED` 与 `RESOLVED_SELLER` 笔数之和 / 筛选订单总数，包含尚在处理的订单作为分母；不称为终局成功率。
- 订单“按积分”分布是订单原价合计，包括待处理或退款状态的订单，不等同于成交积分。
- 账户余额为当前同步快照，**不随日期筛选改变**。订单托管不包含生成冻结或许可报价托管。
- 对比期是所选起始日期之前、长度相同的自然日区间。上期为零时明确显示“上期为 0”，不伪造增长百分比；全部时间不作环比。界面提供对比日期与精确值。
- 连续日期中的无活动日期补零。长区间自动按等长的 N 天分桶，覆盖完整起止范围，最多 90 个点；末尾不足 N 天仍保留。图表标明粒度和每个桶的日期边界。

## 接口与实现

`GET /admin/overview?application_id=<id>&from=YYYY-MM-DD&to=YYYY-MM-DD`。

继续使用现有 Session 与应用范围权限；无 `from/to` 为完整历史。后台在同一个 PostgreSQL 只读、可重复读事务中聚合自己的来源副本，不读取主平台数据库，不改订单和账本。日期边界明确使用 `Asia/Shanghai`，不依赖服务器默认时区。

返回类型见 `packages/contracts/src/analytics.ts`：`range`、`totals`、`comparison`、`orders`、`statuses`、`licenses`、`top_assets`、`balances` 和连续 `trend`。原 `trend.amount` 保留为成交积分。所有积分和计数都以十进制字符串传输；数据库使用精确聚合，前端通过 BigInt 计算比例，只将受限的画图坐标转为 Number。缩写的大数可通过悬停查看完整值，趋势数据表保留精确积分。

图表使用本地 SVG 与 CSS，不增加图表服务或运行时外部请求。趋势可键盘访问；图例、数值与数据表提供颜色之外的信息。手机端改为单列卡片，表格只在自身容器滚动。
