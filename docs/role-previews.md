# 五岗位账号体验

五个独立岗位分别使用独立账号，通过统一登录页 `http://localhost:8920` 登录。每个体验账号只有一个角色，仅授权给本地模拟应用。原有三个初始化账号及其密码、历史记录保留。

```sh
npm run local:role-previews
```

此命令通过现有登录、账号创建及授权 API 操作，会写入既有操作审计；不直接改写数据库，不执行资金命令。仅允许本机地址及当前管理员有权访问的 `mock` / `test` 应用。已有账号与本地凭据完全匹配时可重复执行，不重置密码；冲突、停用或权限发生变化时明确报错，不覆盖其他账号。

| 岗位       | 登录邮箱                             | 主要差异                                                         |
| ---------- | ------------------------------------ | ---------------------------------------------------------------- |
| 系统管理员 | `preview-admin@trade-admin.local`    | 操作员管理、接入配置和审计；没有运营申请或审批角色               |
| 运营处理   | `preview-operator@trade-admin.local` | 我的开放工单、新建/领取/处理工单，以及发起运营申请；不能独立审批 |
| 独立审批   | `preview-approver@trade-admin.local` | 待我审批，可审核其他人员提交的申请；不能创建运营工单             |
| 运营查看   | `preview-viewer@trade-admin.local`   | 查看业务数据和导出；没有人员管理、审计、工单处理或审批入口       |
| 审计       | `preview-auditor@trade-admin.local`  | 查看业务数据、导出和操作审计；没有人员管理、工单处理或审批入口   |

随机密码保存在忽略文件 `.local/role-preview-accounts.json`（0600），不会写入文档、测试日志或 Git。账号展示身份为“岗位体验 · 岗位名”。登录后可在“当前登录身份”核对邮箱、单一岗位与授权应用。

可以依次退出并使用下一账号登录，也可以使用不同浏览器会话同时查看。不同岗位仍可看到共同的业务查询页面，处理按钮和待办由角色决定。审批待办没有记录时会显示 0；只有运营人员提交申请后，审批员才会看到对应的审批任务。

当前版本的共同首页和多数共同菜单尚未按岗位重新组织。已补充 [平台调研](platform-role-research.md) 与 [岗位工作区改造计划](role-workspaces-plan.md)；计划中的五种默认工作区和更细读取权限尚未实施，以本页上述当前行为为准。

## 验证

- `npm test` 使用临时 schema 和合成账号验证五种角色的读取/写入边界、跨应用拒绝、重复运行保留密码、原账号不变，以及真实/正式应用拒绝创建体验账号。
- `npm run test:roles:ui` 验证五个角色分别登录/退出，单岗位身份、人员/审计菜单、个人待办和工单操作按钮；截图在 `.local/ui-tests/role-*.png`，仅含隔离环境合成数据。
- 当前本地创建的五账号只做登录及界面核对；没有用这些账号执行资金操作。
