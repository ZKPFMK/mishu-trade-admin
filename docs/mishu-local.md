# 接入本地 MiShu 主平台

本地后台地址：http://localhost:8920。真实来源应用为 **MiShu 本地主平台**（`mishu_local`），默认优先显示；原 128 笔模拟订单在 **MiShu 模拟演示** 中保留。初始账号密码保持不变，保存在 `.local/credentials.json`。

## 操作顺序

1. 确认主平台已安装 `apps/server/src/routes/tradeAdmin.ts`，并在两个仓库分别提交现有改动、备份数据库。
2. 在本仓库执行 `npm run connect:mishu -- --platform /absolute/path/to/mishu-platform`。
3. 在主平台执行 `npm run local:restart:server`。
4. 在本仓库执行 `npm run build`、`npm run local:restart`、`npm run connect:mishu -- --import`。
5. 登录后台，选择 **MiShu 本地主平台**。在“应用接入”确认初始导入完成、同步正常，再查看“全部订单”。可按完整作品名称或订单编号精确搜索。

配置命令只修改两个忽略的 `.env`、本地连接清单和后台应用/权限元数据，不打开来源 SQLite。已有配置备份保存在 `.local/connection-backups/`，目录 0700、文件 0600。读取 token 不打印，不写入审计或 Git。只授权已有本地管理员查看新应用；其他人员需另行授予应用范围。

命令可重复执行，既有密码、演示数据、真实投影不会重置。重复 `--import` 会复用待处理导入或确认已导入的来源身份，不覆盖已有副本。来源端口可通过配置阶段 `--source http://127.0.0.1:8787` 指定；已接入来源不能直接改指另一个地址或数据库。

## 数据怎样到达后台

用户通过主平台购买或生成 → 主平台正常业务事务与变动标记一起提交 → 主平台内部读取适配器发布完整事件 → 后台 Worker HTTP 拉取 → 校验和写入独立 PostgreSQL → 管理界面自动更新。

接入前的历史通过完整快照导入。Worker 约每 2 秒拉取变动，页面每 10 秒更新；这属于最终一致性，不保证点击购买后后台同一瞬间显示。来源暂时不可用时后台显示连接异常、保留原数据，恢复后从已应用游标补拉。

来源数据仍使用 `CREDIT` 模拟支付。真实来源仅支持查询、导出、对账和工单记录；不会开放退款、调账、强制结算。许可报价与私密检索流水分别归类，不混入作品订单成交统计。

## 联调与排查

```sh
npm run test:mishu -- /absolute/path/to/mishu-platform
npm run local:status
```

联调通过两个独立进程、HTTP 和隔离数据库验证历史导入、真实 SDK 购买/交付/验收、退款同步、生成扣费、许可托管、重启补拉、幂等、搜索、权限和七项对账。测试控制仅走父子进程 IPC，不增加业务测试 HTTP 接口。

若仍查不到记录，先确认当前应用，再检查“应用接入”的初始导入、错误和待应用事件，以及 `.local/worker.log` 中错误码。`source_http_403` 通常意味着两端读取密钥不一致；配置修改后两端都需要重启。不要用普通用户登录 token 或 Prompt 审核凭证替代来源读取密钥。

范围：首版每个部署只连接一个真实来源，完整快照不超过 50 MiB，详细限额见 [接入契约](source-contract.md)。大来源分块导入、在线重建、真实管理命令和生产部署仍需后续实施。
